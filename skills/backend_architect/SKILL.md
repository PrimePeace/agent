# 后端结构

沿用方案角色的结论，不在这一步推翻选型。单体用包边界，微服务用网络边界。服务之间不共享数据库。

## 模块职责

- api：校验、认证、协议转换。不写业务规则，不直接访问数据库。
- domain：状态机和不变式。订单从创建到完成允许哪些跳转，写在这里，不写在控制器里。
- persistence：参数化查询或 ORM，禁止拼接 SQL。只被 domain 调用。
- identity（需要登录时）：统一校验调用方身份，业务模块不自己解析令牌。
- messaging（微服务时）：只投递本服务发件箱里的事件，不直接调用别的服务的库。

## 数据

MySQL 是事实来源。满足其一才加 Redis：原文有峰值或延迟要求；读写比明显偏读。Redis 只放可以丢掉重建的读模型，不放事实。

实体至少有 id、status、version、createdAt、updatedAt。version 做乐观锁：更新时带上读到的版本号，版本不匹配返回冲突，让调用方重读。不要用整表锁解决并发。

状态机示例（订单）：`CREATED → PAID → SHIPPED → DONE`，任何状态可到 `CANCELLED`，但 `SHIPPED` 之后取消要走退货流程。非法跳转返回 409，不要静默忽略。

## 错误码

前缀取业务对象，例如订单用 `ORDER-`。约定：

| 码 | HTTP | 含义 |
| --- | --- | --- |
| XXX-4001 | 400 | 字段缺失或格式不合法 |
| XXX-4004 | 404 | 资源不存在 |
| XXX-4009 | 409 | 状态冲突或幂等键被占用 |
| XXX-4010 | 401 | 未认证 |
| XXX-5000 | 500 | 系统故障，日志带请求标识，响应不回传堆栈 |

业务错误和系统错误分开：业务错误调用方改参数能解决，系统错误调用方只能重试或等待。

## 安全底线

- SQL 一律参数化。任何从请求里来的值都不进字符串拼接。
- 密码只存 bcrypt 或 argon2 哈希。
- 口令、密钥来自环境变量或密钥管理服务，不进代码、配置文件和镜像。
- 对外错误只含错误码和可公开说明，不含堆栈、SQL、内部路径。
- 写接口校验类型、长度、枚举。状态字段由服务端计算，不信任调用方传入。
