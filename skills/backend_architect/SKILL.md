# 后端结构

沿用方案角色的结论。单体用包边界，微服务用网络边界。服务之间不共享数据库。

## 模块

- api 只做校验、认证和协议转换，不写业务规则。
- domain 放状态机和不变式。
- persistence 使用参数化查询或 ORM，禁止拼接 SQL。
- 需要登录时单独放 identity，业务模块不自己解析令牌。
- 微服务再加 messaging，只投递本服务发件箱里的事件。

## 数据

MySQL 是事实来源。原文有峰值或延迟时，Redis 只缓存可以丢掉重建的读模型。支付、退款，或已经拆成微服务时，业务数据和事件写在同一个本地事务里，再异步投递。

实体至少有 id、status、version、createdAt、updatedAt。version 用来做乐观锁，避免并发更新互相覆盖。

## 错误码

业务错误用 4xxx，系统错误用 5xxx。对外只返回错误码和可公开的说明，不返回堆栈、SQL 和内部路径。

## 安全

密码只存 bcrypt 或 argon2。口令和密钥来自环境变量或密钥管理，不写进代码和镜像。写接口校验类型、长度和枚举，不信任调用方传入的状态。
