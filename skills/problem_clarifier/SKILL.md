# 问题梳理

先回答四件事：谁在用、要完成什么动作、怎样算做完、哪些条件已经写明。这四件里缺了能执行的目标，就停下来问，不要把猜测交给方案角色。

## 必须写进简报

- 用原文复述问题，点明业务对象。用户、管理员是调用方，不是资源，除非句中没有订单、商品这类业务名词。
- 约束只记录原文里出现的峰值、延迟、一致性和范围。没写的放进假设，并标明这是假设。
- 验收标准要能判定对错。至少包含创建、按标识读取，以及写请求重复提交不会产生第二笔数据。
- 盲区逐项标成已覆盖或未决。未决项写成一个具体问题，不要写成「待定」。

## 默认要检查的盲区

身份与权限、幂等与重复提交、失败与补偿、数据保留、可观测性、容量、租户隔离。

业务有额外盲区时，写在下面，下一次梳理会把这段知识交给宿主。服务仍按内置规则打分；这里的条目用来提醒宿主不要漏问。
