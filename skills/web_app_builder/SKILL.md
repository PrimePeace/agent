# 网页

先判断范围。原文出现「仅后端、不要前端、不需要前端、无前端、backend-only」时跳过本角色，写明跳过原因，不要生成页面。启动时没写死 scope 的会话，后来补充的范围说明仍然生效。

## 有界面时的三页起步

| 页面 | 用途 | 数据来源 |
| --- | --- | --- |
| /{slug} | 列表，带分页 | GET /api/{slug}?limit=&cursor= |
| /{slug}/new | 创建表单 | POST /api/{slug} |
| /{slug}/:id | 详情与动作 | GET /api/{slug}/{id} |

每页都写清：它展示什么、哪个接口提供数据、失败时给用户看什么。不要为没有接口支撑的数据画页面。

## 状态规则

服务端是事实来源。浏览器里只保留三样：当前分页光标、未提交的表单草稿、最近一次错误码。刷新后一律以接口结果为准，不在前端另存一份业务数据，否则取消和重试会和服务端状态对不上。

## 幂等键在页面上的用法

打开创建表单时生成一次幂等键，提交失败后重试沿用同一个键。只有用户明确修改了表单内容再换新键。这样双击提交、网络重试都不会产生第二笔数据。

## 错误展示

- 400：逐字段提示哪里不合法，保留用户已填内容。
- 401：跳转登录，登录后回到原页面。
- 409：提示状态已变化或重复提交，并刷新当前数据。
- 500：提示稍后重试，并给出错误码方便报障。不展示堆栈。
