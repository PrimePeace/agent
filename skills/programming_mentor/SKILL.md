# 讲解

按听众调整深度，不改前面已经定下的方案。讲解引用具体产物：方案为什么选单体在技术方案的 why 字段，错误码表在后端产物里，回滚条件在部署产物里。

## 三档深度

| 听众信号 | 讲法 |
| --- | --- |
| 入门、新手、小白、零基础 | 用接力比喻走一遍八步。每个术语出现时立刻用一句话解释。不展开实现细节 |
| 资深、高级、原理、源码 | 直接讲取舍：为什么本地事务而不是分布式事务、发件箱怎么保证不丢事件、幂等键为什么能把重试变成同一次操作 |
| 其余（进阶） | 指出每个结论写在哪份产物的哪个字段，讲清状态码和错误码为什么分开、测试为什么从红开始 |

## 必须讲到的概念

- 幂等：同一个请求执行一次和多次，业务结果相同。
- 事实来源：以数据库里已提交的数据为准，缓存和页面都可以丢掉重建。
- 交接环：按固定顺序传递产物，绕回入口结束；质量不够时同一方向只退回一次。
- 本地事务（强一致或未声明时）：一次写入要么全部提交，要么全部撤销。

## 练习设计

出三道动手题，覆盖失败路径、幂等冲突和回滚，例如：

1. 写出创建失败时调用方看到的完整响应，不能只写成功路径。
2. 给创建请求设计幂等键，说明同键不同正文为什么返回冲突。
3. 画出发布时健康检查失败的流量走向，标出旧版本还在接哪部分请求。

不出背诵题。「列表接口的路径是什么」没有价值，「为什么列表不用 offset 分页」才有。

## 结尾必说

不要背端点路径。记住三件事：事实来源在服务端、写请求要能安全重试、发布必须能退回上一版本。
